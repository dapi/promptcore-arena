# Локальный прототип

## Запуск

Нужен Node.js 22+. Сторонние npm-зависимости отсутствуют.

```sh
git clone https://github.com/dapi/promptcore-arena.git
cd promptcore-arena
npm start
```

Команда запускает приложение на `127.0.0.1` и открывает браузер. Если установлен `port-selector`, используется стабильный порт проекта; иначе свободный порт выбирает система. `npm run dev` запускает без открытия окна. Если приложение уже запущено, открой напечатанный им адрес.

## Codex

Прототип использует установленный и авторизованный Codex CLI, проверенный с версией `0.160.0`. Проверить вход: `codex login status`; при необходимости войти: `codex login`. Установка описана в [документации Codex CLI](https://developers.openai.com/codex/cli).

На каждом ходу приложение одновременно запускает два `codex exec`. Каждый получает только собственное наблюдение, фиксированный промпт и свою краткую память. Движок выдаёт `legalActions` — список допустимых действий с номерами. Codex возвращает `choice`, комментарий и память; для каждого хода создаётся JSON Schema с enum допустимых номеров. Адаптер переводит номер в игровую команду, движок повторно проверяет её и одновременно рассчитывает оба действия. MCP для управления бойцами не используется. `previousAction` сообщает бойцу об ошибке или столкновении на прошлом ходу. Модель и reasoning выбираются в интерфейсе и одинаковы для обоих бойцов. При старте сервер запрашивает каталог через `codex app-server`, JSON-RPC `initialize` → `model/list`; список моделей и поддерживаемые уровни reasoning не зашиты в приложение. Учитываются скрытые модели и пагинация. Для быстрого старта по умолчанию выбирается `gpt-6-luna`; `ARENA_CODEX_MODEL` меняет предпочтительную модель: она используется, только если есть в полученном каталоге; иначе выбирается первая доступная. Начальный reasoning — `low`, если поддерживается, иначе рекомендованный Codex. При ошибке каталога запуск Codex блокируется с пояснением; тренировку можно выбрать вручную. Перезапуск приложения обновляет каталог.

Отдельный API-ключ не требуется. Используется текущая авторизация Codex, поэтому расчёт матчей расходует доступные лимиты этой учётной записи. Один матч требует до 80 запросов, серия из четырёх — до 320. Интерфейс и движок локальны, Codex обращается к своей модели через интернет.

Боевые вызовы запускаются с `--ignore-user-config`, `--ignore-rules`, `--ephemeral`, `--sandbox read-only` в отдельных временных пустых каталогах. Shell, MCP из пользовательской конфигурации, плагины, hooks, браузер, computer use, поиск в интернете, skills и делегирование отключены. `project_doc_max_bytes=0` исключает инструкции из AGENTS.md из контекста бойца. Авторизация остаётся штатной; пользовательская конфигурация Codex не изменяется. Каталоги удаляются после ответа. Дополнительная проверка событий CLI останавливает матч при использовании стороннего инструмента.

Лимит одного запроса зависит от reasoning: `low` и остальные начальные уровни — 90 секунд, `medium` — 120, `high` — 180, `xhigh` — 240, `max` — 300, `ultra` — 360. Уровни становятся доступны только по данным каталога. Ошибка запуска или модели завершает матч с понятным статусом; рассчитанные ходы остаются доступными. Автоматической подмены на тренировочных ботов нет. Неверное игровое действие означает пропуск хода. Кнопка остановки прерывает оба процесса; незавершённый бой не засчитывается как ничья.

Официальная документация: [неинтерактивный запуск Codex](https://learn.chatgpt.com/docs/non-interactive-mode), [настройки Codex](https://learn.chatgpt.com/docs/config-file/config-reference), [протокол App Server и каталог моделей](https://learn.chatgpt.com/docs/app-server).

## Интерфейс

- **Арена:** две общие карточки бойцов со стратегиями и показателями, выбор модели и reasoning или тренировки, настройки карты и стартов в меню в шапке поля, запуск матча и серии из четырёх боёв.
- **Бойцы:** редактируемые имена до 24 символов. Первоначально назначаются два разных аватара из шести. Клик по аватару переключает его до, во время и после боя; новый запуск сохраняет выбранный облик. Цвета закреплены: A — голубой, B — фиолетовый; отдельные поля выбора внешности убраны. Карточка и Canvas используют один SVG. Аватары сохраняются в черновике и реплее; смена внешности не затрагивает игровые кадры.
- **Стратегия:** после запуска промпт доступен только для чтения, в том числе при просмотре записи. После завершения или остановки «Изменить для нового боя» открывает редактируемый черновик; стратегия сохранённого матча не меняется.
- **Расчёт:** сразу после запуска появляются индикатор, номер хода, таймер и этап работы каждого бойца. На поле думающие бойцы парят с анимированными кольцами, ответивший боец отмечен «ГОТОВ». Справа — полученные сообщения Codex, краткие пояснения, если модель их публикует, и причина действия; JSON раскрывается по клику. Сообщения сохраняются для просмотра по ходам и скрываются для соперника в режиме обзора одного бойца.
- **Повтор:** Canvas-анимация движения, выстрелов, щита, сканирования и ловушек; здоровье, энергия, контроль, события и комментарии. Пауза, четыре скорости, шаг назад/вперёд, перемотка, обзор всей карты или одного агента. Клавиши: пробел и стрелки, когда фокус вне полей ввода.
- **Результат:** итоговая таблица со здоровьем, контролем ядра и собранной энергией каждого бойца; решающий показатель выделен. При лимите ходов причина победы указывает конкретный критерий.
- **История:** сохранённые матчи, восстановление промптов и параметров для нового запуска. Каждый реплей можно скачать как JSON.
- **Серия:** две карты, по два матча с обменом стартами. Итоги по победам и ничьим, отдельный просмотр каждого матча.
- **Тренировка:** встроенные боты, без обращений к модели. Свободный текст промпта не управляет тренировочными ботами; интерфейс явно это показывает.

На компьютере арена занимает высоту окна: шапка 44 px, карта подстраивается по ширине и высоте. Имя, стратегия, здоровье, энергия и счёт объединены в карточке каждого бойца. Во время боя настройки запуска скрыты; справа переключаются «Сообщения» и «Хроника». Длинные промпты и журналы прокручиваются внутри своих областей. На мобильном сохраняется вертикальная компоновка. В новой механике батарейки исчезают при входе, каждые 6 ходов заменяются новой волной; зона переезжает каждые 8 ходов, следующая показана пунктиром за 2 хода. При спорном контроле никто не получает очков. Неизменённые старые шаблоны стратегий автоматически заменяются на тактика и охотника; пользовательские тексты сохраняются. Меню карты открывается рядом с её названием, закрывается по Escape и клику снаружи. Код карты и смена стартов сохраняются в черновике; во время боя их изменение заблокировано.

При расчёте через Codex сразу показывается последний рассчитанный ход. Полоса повтора (пауза, шаги, перемотка, скорость) и её горячие клавиши доступны после завершения или остановки запуска, если записан хотя бы один ход. До старта и во время расчёта полоса скрыта. Карта, показатели и сообщения повтора синхронизированы с выбранным ходом. При просмотре архивной записи во время активного запуска кнопка «В эфир» возвращает к текущему бою. Сохранённый бой проигрывается без запросов к модели. `prefers-reduced-motion` отключает анимации перемещений и эффекты.

Сервер читает JSONL-события `codex exec --json` по мере поступления и передаёт их браузеру через SSE (`/api/jobs/:id/events`). Повторное подключение учитывает `Last-Event-ID`, опрос состояния остаётся резервным каналом. Перезагрузка страницы восстанавливает наблюдение за активным боем. Это поток доступных событий CLI, без гарантии вывода каждого токена или пояснений на каждом ходу. Запрашивается `model_reasoning_summary="concise"`; сырой внутренний reasoning и stderr не передаются зрителю.

Логотип и favicon берутся из `site/logo.svg` и `site/favicon.svg`: локальная игра, страница проекта и README используют одни исходники. Файлы в `branding/` — эскизы.

## Данные и устройство

- `src/engine-v1.mjs` и `docs/rules-v1.md` — сохранённые движок и правила старых записей.
- `src/engine.mjs` — правила `arena/2`, чистые функции: карта, наблюдение, проверка действий, одновременное разрешение хода.
- `src/agents.mjs` — встроенные боты и адаптер Codex CLI.
- `src/navigation.mjs` — подсказки маршрутов по наблюдению и уже увиденным стенам. Цель и действие выбирает модель.
- `src/codex-models.mjs` — получение каталога Codex и лимиты времени по reasoning.
- `src/codex-events.mjs` — разбор JSONL и отбор публичных событий Codex.
- `src/server.mjs` — локальный HTTP API, запуск/отмена, серия и атомарное сохранение реплеев.
- `web/fighters.js` — имена, палитра и общий источник SVG аватаров.
- `web/sound.js` — эффекты Web Audio без внешних аудиофайлов, отключение звука сохраняется локально. Звук начинается только после действия пользователя; пауза и скрытие вкладки обрывают текущие эффекты, перемотка ползунком беззвучна.
- `web/` — игровое приложение, без CDN и внешних шрифтов.
- `site/` — отдельная существующая публичная страница проекта с постановочной демонстрацией.
- `.arena/matches/` — полные JSON-реплеи (промпты, имена и внешность бойцов, наблюдения, действия, события, сообщения модели, кадры, модель и reasoning).
- `.arena/last-prompts.json` — промпты последнего запуска; черновики также сохраняются в localStorage браузера.

`.arena/`, артефакты проверки и временные файлы исключены из Git. Сервер слушает только loopback, проверяет Host/Origin и отдаёт только разрешённые ресурсы из `web/` и два файла логотипа из `site/`. После перезапуска сервера активный бой не возобновляется: уже записанные ходы доступны в истории как незавершённый бой. Одновременно рассчитывается один матч или одна серия.

[Полная спецификация правил](rules.md).

## Проверки

```sh
npm test
npm run check
```

Тесты проверяют симметрию и связность карт, коллизии и обмен позициями, одновременный урон, защиту и ловушки, прежнее деление энергии и новый автоматический подбор батареек, смену/оспаривание зоны, бесплатное движение, отсутствие автозаряда, допустимые команды, маршруты без раскрытия скрытой карты, ограничение видимости, завершение матча, точное воспроизведение, сохранение, серии, ошибки провайдера, отмену, каталог моделей, проверку пары модель/reasoning, её передачу обоим бойцам в серии и сохранение аватара без изменения кадров.

HTTP-тесты используют отдельную временную папку и свободный локальный порт. Они не вызывают настоящую модель. Браузер проверяется через `playwright-cli` с управляемым headless Chromium; сценарий находится в `scripts/browser-check.js` и требует запущенного приложения. Он создаёт тренировочные матчи в локальной истории. Проверка настоящего Codex выполняется отдельным матчем через интерфейс.

```sh
playwright-cli -s=arena-check open "http://127.0.0.1:$(port-selector --name web)" --config=scripts/playwright.config.json
playwright-cli -s=arena-check run-code --filename=scripts/browser-check.js
playwright-cli -s=arena-check close
```

Снимки экрана сохраняются в `artifacts/` (создать папку перед проверкой).

## Границы прототипа

Баланс пока экспериментальный. Карты симметричны, но разные промпты и недетерминированные ответы модели требуют серии матчей для сравнения. Реплеи версионированы: движок направляет `arena/1` в сохранённую реализацию, Canvas рисует прежние источники и неподвижное ядро. `arena/2` использует батарейки и подвижную зону. Игровые состояния не переписываются при обновлении. Публикация приложения, аккаунты и доступ по сети относятся к возможному следующему этапу.
